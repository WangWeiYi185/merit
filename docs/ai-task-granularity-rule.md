# AI 规范与任务颗粒度规则

适用于用 AI 执行的仓库规范、存量改造和重复工作流。以独立查阅、独立评审和独立验证作为拆分依据。

## 1. 入口只写触发条件和链接

根 `AGENTS.md` 说明何时读取哪份规范。各规范的具体条款、目录树、操作步骤和验收要求放在对应文档中。涉及多个技术栈时，由索引定位相关文件。已知文档路径时可以直接读取。

## 2. 按主题和技术栈拆分规范

一份文档回答一类问题。各技术栈的文件树、命名和归属规则分别维护。多处适用的规则集中维护一份，相关任务按需引用。操作手册依赖对应规范，例如存量迁移手册从目录规范获取目标路径。仓库的具体规则和例外写在对应规范中。

## 3. 一次任务交付一批可独立验收的改动

开始前明确任务模式、目标模块、允许改动的范围、交付物和验收方式。以能一起验证的改动为一批。比如文件移动及其必要引用更新属于同一批，能独立验收的其他模块另开任务。

需要规划和执行时，以清单交接。记录基准、源路径、目标路径、归属依据、联动文件和验证方式。执行按清单开展，遇到清单之外的必要改动时先记录路径和原因，依据已授权的范围决定是否纳入本批。

## 4. 按当前任务加载材料

只读取当前任务需要的技术栈、模块、阶段和受影响文件。新任务可以从交接清单接续。重复流程可以封装为 Skill，由 Skill 引用仓库规范，并用脚本校验路径冲突、改动范围等可机械判断的条件。

## 5. 分阶段评估 Skill

规划看文件归属准确性和覆盖率。执行看越界改动、遗漏引用和首次验证结果。另记人工评审时间、返工轮次，以及可获得的输入 token 或实际读取范围。做对照时固定模型、源码基准、规范和验收要求。比较执行效果时，两组使用同一份清单。
