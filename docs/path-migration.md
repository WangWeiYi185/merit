# 存量路径迁移手册

## 1. 目标路径的依据

先定位仓库的结构规范。使用本工具包时，从 [目录规范索引](project-structure.md) 打开当前技术栈的文档，并核对模块适用的项目例外。该规范提供职责划分和目录层级，业务目录名沿用仓库已有名称；树中的 `shop`、`order`、`checkout` 是分类案例，不作为新建路径。迁移手册负责盘点、规划、执行和验收。遇到规范缺失或规则无法确定目标时，将文件列入待判断项。已有仓库规范时使用该仓库的规范。

一次性迁移可以直接开任务并引用结构规范。需要在多个模块或仓库重复迁移时，可调用 `$project-structure-migration`，用清单交接并运行路径检查。

## 2. 原子迁移与任务交接

以**可以独立评审和验证的一组移动及其必要引用更新**作为一个批次。比如将 `CheckoutView.swift` 和 `CheckoutViewModel.swift` 归回结账模块，同时更新实际存在的 Xcode 路径引用。批次大小以改动关联和验证成本决定。

### 规划任务

> 使用 `$project-structure-migration` 规划 iOS 的 Checkout 批次。按仓库规范定位文件，输出含基准提交、源路径、目标路径、归属依据、联动文件、验收命令和待判断项的清单。任务只做规划。

只扫描模块和直接相关的引用。每条移动记录引用实际适用的规范文件及相关规则，或项目例外，目标路径缺少依据的文件进入待判断项。规划输出的 JSON 是可评审的交接件。

### 执行任务

> 使用 `$project-structure-migration` 执行 `/absolute/path/checkout-plan.json` 中的这一批迁移。按清单同步修改引用，校验差异，运行构建和相关测试。

建议用新会话接收清单。执行时读取清单、对应技术栈的规范文档和受影响文件，发现范围外依赖时明确给出路径、原因和执行状态。独立的重命名清理、重构或其他业务迁移留给下一批。

## 3. 验证本批改动

- 校验清单中的源路径、目标路径和联动文件，再对照 Git 差异检查范围。
- 移动文件时同步更新受影响的引用、资源路径和构建配置，并核对文件归属。例如 iOS 检查 Xcode target、资源及工程生成配置，Flutter 检查 Dart 导入与导出、`pubspec.yaml` 资源路径和受影响的宿主工程。
- 运行仓库现有构建和相关测试，记录实际命令、结果和待处理项。

## 4. 如何量化 Skill 的效果

在相同起始提交上，为每个案例使用独立会话和工作树，固定模型、推理设置、目录规范、权限和验收命令。一组使用普通任务提示，一组显式调用 Skill。使用同一评审口径，并把规划与执行分开计量。

| 指标 | 记录方式 |
|---|---|
| 规划准确率 | 人工接受的目标路径数 ÷ 建议路径数。没有建议时记为不适用。 |
| 规划覆盖率 | 正确识别的应迁移文件数 ÷ 人工认定的应迁移文件数。另记合理留待判断的条目。 |
| 范围偏差 | 实际改动中超出清单的唯一路径数。将移动的源路径和目标路径都纳入比较。 |
| 迁移完整性 | 首次项目构建和相关测试分别记录通过、失败或未运行。另记漏改引用数。 |
| 评审成本 | 记录人工评审分钟数、要求修正的条目数和往返轮次。 |
| 上下文成本 | 有会话统计时记录输入 token。否则记录读取文档、章节数和扫描范围，作为近似指标。 |

**分开测两个阶段。** 规划对照用相同源码和需求比较两组清单。执行对照给两组同一份经人工校对的清单，比较路径差异和验证结果。这样可以定位是规划归类、执行改动还是评审成本发生了变化。

| 案例 / 基准提交 | 阶段 / 版本 | 建议 / 接受 / 漏项 | 越界 / 漏改 | 首次构建 / 测试 | 评审分钟 / 轮次 | 输入 token 或读取范围 |
|---|---|---|---|---|---|---|
| Checkout / 待填写 | 规划或执行 · 普通任务或 Skill | — | — | — | — | — |

优先用现有项目里的一个小模块试跑。若越界多，先收窄批次或补齐联动路径。若漏改集中在某类构建配置，再给相应技术栈加检查。保留每个案例的原始结果，便于复核 Skill 版本间的差异。

## 5. 安装与调用

从 AIWorkflow 仓库取用以下内容：

- 将所需的 `docs/structure/` 文档放入目标业务仓库。使用 [目录规范索引](project-structure.md) 时，连同索引中所列文档一起复制，或把索引调整为目标仓库实际使用的技术栈。已有结构规范时，可在任务里直接指定文件。
- 按需复制 `docs/path-migration.md`，将 `templates/project-structure/AGENTS.md` 中的两条入口合并到目标仓库根 `AGENTS.md`。
- 在 Pi 中用 `pi --skill /path/to/AIWorkflow/skills/project-structure-migration/SKILL.md` 加载，进入 Pi 后调用 `/skill:project-structure-migration`。
- 在 Codex 中，将 AIWorkflow 的 `skills/project-structure-migration/` 复制到目标仓库的 `.agents/skills/project-structure-migration/`，然后显式调用 `$project-structure-migration`。

分层和任务颗粒度规则见 [AI 规范与任务颗粒度规则](ai-task-granularity-rule.md)。
