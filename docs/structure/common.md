# 通用目录规则

- **关注点分离。** 将界面、状态、业务逻辑、数据访问和通用基础设施按职责放置。少量代码可以先在同一模块内平铺。
- **高内聚、低耦合。** 优先复用已有业务模块及其命名，业务专属文件就近归属。同一业务的界面、状态和数据访问可以放在同一个业务模块下，模块之间通过公开入口、接口或协议协作。确认有跨模块用途后再提取共享代码。
- **命名一致性。** 项目选定同类目录名后统一使用，例如 `pages/`、`features/`、`tests/`，业务目录使用对应业务词。各技术栈规范中，Web 多词业务目录用 `kebab-case`，iOS 源码目录用 `PascalCase`，Dart 和 Python 用 `snake_case`，Java、Kotlin 和 Go 示例包名用小写。框架或构建工具规定的路径沿用其名称。
- **目录树默认聚合。** 以磁盘路径为准，从主要源码目录展开两层，保留入口、模块、资源、测试和必要的构建配置。按需展开指定模块，省略依赖缓存、构建产物和生成文件明细。建议路径单独标注，方便与实际路径比对。
