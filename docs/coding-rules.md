# 编码任务的通用规则加载索引

本索引由 AIWorkflow 主 Skill 调用，适用于已进入 AIWorkflow 的任务。通用规范由 AIWorkflow 提供；业务源码、项目约定和业务证据仍归业务仓库。加载是 Agent 按指令读取文件，不是 CLI 或 Pi 自动注入，也不要求单独安装每项语言 Skill。

## 1. 从哪里读取

以当前实际加载的 `skills/ai-workflow/SKILL.md` 为入口，先解析其真实路径（包括符号链接），再从文件所在的 `skills/ai-workflow/` 目录向上两级得到 AIWorkflow 根目录。以下 `AIWorkflow:` 表示这个根目录，不是磁盘目录名、CLI 参数或 Graphify 路径。

- `AIWorkflow:docs/...`、`AIWorkflow:skills/...` 都从 AIWorkflow 根目录定位，不从业务仓库 cwd 定位。
- 本索引中的 Markdown 链接相对于本文件；进入语言 Skill 后，其内部链接相对于该 Skill。
- 不写死 `/Users/...`，不要求将通用规范复制进业务仓库或修改业务仓库 AGENTS.md。对业务任务将这些通用规范视为只读引用，项目特例只写入业务仓库约定或当前任务，不反写共享文档。
- 若只复制了主 Skill、配套资源缺失，报告具体缺失路径，先恢复配套资源；不从业务仓库或同名全局 Skill 静默替代。

## 2. 按当前任务选最小集合

先读业务仓库适用的 AGENTS.md（包括子目录约定）、构建配置、受影响文件及直接相关调用，确认实际语言、平台、模块和本阶段要做的事。不扫描全部技术栈，不因仓库包含某种语言就加载它的规范。

| 当前任务的触发条件 | 必读资源 | 加载时机与范围 |
| --- | --- | --- |
| 新建、移动、重命名文件，设计模块/目录归属或输出文件树 | [目录规范索引](project-structure.md)，再选对应技术栈文档 | 设计归属时读；已知准确文档路径可直接读，避免重复遍历 |
| 涉及通用目录命名、职责分离或文件树输出 | [通用目录规则](structure/common.md) | 只读当前问题相关条款；不机械创建案例目录 |
| 编写、修改或审查 Swift 代码/API | [Swift API 设计指南](../skills/swift-api-design-guidelines/SKILL.md) | 编码前读；API 设计时提前读，审查时沿用适用条款；它不是完整架构/并发/UI 规范 |
| 编写、修改或审查 Objective-C/Cocoa 代码/API | [Objective-C Cocoa 约定](../skills/objective-c-cocoa-guidelines/SKILL.md) | 编码前读；API 设计时提前读，审查时沿用命名、头文件和契约条款 |
| Swift 与 Objective-C 混编或互操作变更 | 上述语言规范中与两侧实际受影响声明/调用有关的部分 | 不因项目混编而全量读取未涉及语言；检查桥接和公开契约 |
| 仅文档、取证或不涉及上述语言/目录问题 | 不加载无关资源 | 若文档任务输出文件树，则只触发对应目录规则 |

判定依据：`.h` 可能属于 C、C++ 或 Objective-C，结合声明、引用方和 target 判定；`.mm` 只对 Objective-C/Cocoa 部分应用对应指南，其 C++ 部分沿用项目规则。Swift Package 不必是 iOS，不能仅凭 `.swift` 加载 [iOS 目录规范](structure/ios.md)；只有目标平台及模块确实适用时才选择它。其他技术栈从目录索引选取，不加载整个 `docs/structure/`。

已有文件内的局部实现修改、没有目录归属问题时，可只加载语言规范和项目约定；不是每次编码都必须读取目录规范。涉及新建测试文件时，先用对应技术栈规范确定测试归属。

## 3. 单任务记录与续接

在确认任务前，于任务正文「适用规范」记录选中的资源及适用原因。记录路径和相关章节，不复制规范全文；不要仅写“遵循所有规范”。例如：

```markdown
## 适用规范

- AIWorkflow:docs/structure/common.md — plan/execute/verify；新增文件命名与模块职责。
- AIWorkflow:docs/structure/ios.md — plan/execute/verify；新增 iOS 模块测试的归属。
- AIWorkflow:skills/swift-api-design-guidelines/SKILL.md — execute/verify；本任务 Swift 方法命名与参数标签。
- 项目:AGENTS.md — plan/execute/verify；沿用现有模块和测试目录。
- 项目例外：旧模块目录已由构建配置固定，仅新增本任务文件，不迁移旧代码。
- 版本依据：记录实际使用的文档修订或当前工作区状态；重要约束写明具体条款。
```

`项目:` 从目标业务仓库根目录解析；项目内规范继续由业务仓库维护。如果当前任务不适用通用编码规则，可以明确写“不适用：仅修改业务说明，无代码/文件树变化”，不为凑齐记录而加载文档。

- 规划：选择会影响本任务设计、文件归属及验收的规则；有歧义先澄清。
- 编码：动手前按记录读取适用规则，补充实际技术栈证据，不加载无关规则。
- 续接：先读当前任务「适用规范」，从新的实际安装位置解析 AIWorkflow 引用，读取本阶段所需条款。旧任务没有该节时，在当前任务内判断并记录；若需修改已确认正文，先按工作流暂停并重新确认。
- 审查：`flow audit <需求ID> <任务ID>` 展示同一份记录；按适用规范检查本次实际差异、API、文件归属及项目例外。
- 选择、适用范围或例外变化属于任务正文变化，已有确认会失效；不要在已确认任务里静默换规则。文档正文不做自动版本锁定；更新可能影响已确认设计时，先核对差异并重确认。

对语言 Skill 沿用 `flow skill ... --stage ... --task ... --purpose ... --evidence <实际解析路径>` 声明；文档引用以任务正文为准，不伪装成已注册 Skill。Pi 的观察记录仅覆盖其支持的读取方式，不能据此声称所有文档已自动审计。

## 4. 项目约定与通用规则冲突

业务仓库明确的 AGENTS.md、模块约定、格式工具、构建要求、兼容性和业务契约优先；通用规则补充未明确的部分。记录具体例外及依据，不为统一命名或目录风格改变公开 API、序列化字段或移动无关旧代码。

若项目约定之间矛盾、归属无法确定，或冲突会影响公开契约和验收，报告路径、差异和最小解决选项，按 decision/evidence 阻塞，不擅自覆盖规则。不以任何风格规范为理由降低安全、校验、错误处理和数据保护要求。

## 5. 与 Graphify 的分工

- 通用规范回答“应当怎么组织和编写”，由 AIWorkflow 按需读取，并记录在「适用规范」。
- Graphify 回答“当前任务源码如何关联”，仅分析任务允许的业务源码镜像。
- 不把 AIWorkflow 外部规范加入目标仓库的 GRAPHIFY_INPUT 或 READ_ONLY_EVIDENCE，不把 `AIWorkflow:`/`项目:` 标记作为 Graphify 路径，也不放宽仓库外路径限制。
- 若某份业务仓库内部规范需要作为确定性上下文证据，可另按 Graphify 原有规则列精确仓库相对路径；规范选择与证据白名单不是同一件事。

任务记录表示选择了哪些规范，Skill 读取记录表示文件被读过，两者都不证明代码已正确遵守；最终仍核对实际差异、测试与人工审阅。
